# Pin rationale (verified on PyPI 2026-10-24, release dates in brackets):
# - transformers 4.48.3 [2025-02] is contemporary with the 0.45.x bitsandbytes
#   line; peft 0.18.1 [2026-01] is contemporary with the 0.49.x line.
# - bitsandbytes: 0.45.0 -> 0.49.2 because Colab's torch is 2.11.0+cu130 and
#   0.49.2 [2026-02] is the newest release from the peft-0.18.1 era. Still
#   UNVERIFIED at runtime until Stage 12 of the next notebook run - if it
#   fails, record the error and re-pin against the newest release (0.50.2).
# - librosa 0.10.2.post1 [2024-05]: 0.10.4 was never published on PyPI
#   (registry 404; the librosa line jumps 0.10.2.post1 -> 0.11.0), and the
#   1.0.0 major [2026-08] is intentionally NOT pinned.
# - soundfile 0.12.1 -> 0.13.1 [2025-01]: FLAC decode (FLEURS) is proven on
#   the 0.13.x line by notebook Stages 6/7 (runs 2-3).
# - sentencepiece 0.2.0 -> 0.2.1 [2025-08] after run 4: 0.2.0 ships wheels only
#   for cp36-cp312 (registry-verified 2026-10-24), so Colab's Python >=3.13
#   fell back to a source build, which failed. 0.2.1 publishes manylinux
#   cp313/cp314 wheels. 0.2.2 [2026-07] also does but is deliberately NOT
#   pinned (same conservatism as bnb 0.50.2 / librosa 1.0.0). Stage 2 runs pip
#   with --only-binary=:all: so any future pin without a wheel fails fast
#   instead of attempting a doomed source build.
# - torch/torchaudio come from the Colab preinstalled GPU image; we do NOT
#   pin them here to avoid breaking the preinstalled CUDA build.
# - bitsandbytes is Linux/Colab-only (QLoRA). It is intentionally absent from
#   any Windows/local requirements until a serving target is chosen (Phase 4).
# - huggingface_hub is installed transitively with transformers/datasets.
